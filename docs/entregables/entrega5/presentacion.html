Introducción · 1 min

¿Qué es el phishing y qué construimos?

El phishing es un ataque donde un sitio falso imita a uno legítimo para robar credenciales o datos bancarios.

Lo que construimos

  • Un clasificador de sitios web (phishing vs legítimo)
  • Entrenado con el dataset UCI Phishing Websites: 11 055 sitios, 30 features, codificación ternaria
  • Desplegado como un servicio de detección en tiempo real

Dataset

11 055 instancias etiquetadas

30 features en 4 categorías: URL, HTML/JS, anomalías, dominio

Clases balanceadas: 55.7% legítimo / 44.3% phishing

4.8 M

ataques de phishing en 2024 — récord histórico (APWG)

< 24 h

vida útil típica de un sitio phishing antes de ser bloqueado

$2.8 B

pérdidas por fraude de correo empresarial en EE. UU.

¿Por qué machine learning?

  • Listas negras: reactivas — el sitio ya hizo daño antes de listarse
  • Reglas manuales: se evaden fácilmente y requieren mantenimiento constante
  • ML: aprende los patrones directamente de los datos, sin codificar reglas a mano

Implementación · 3 min

Clasificación asíncrona (inicio del semestre)

Pipeline offline

  • Carga del dataset UCI → preprocesamiento con StandardScaler
  • División estratificada: 70% train · 15% val · 15% test
  • Entrenamiento del MLP: 128→64→32→1, BatchNorm + Dropout + L2 + Early Stopping
  • Comparación con Random Forest (100 árboles) y SVM (kernel RBF)
  • Modelo y scaler guardados en disco para inferencia

15 105 parámetros · convergencia en ~45 épocas

Implementación · 3 min

Clasificación en tiempo real

① API REST (FastAPI)

El modelo entrenado se expuso como servicio web. Recibe una URL, extrae los 30 features en vivo y devuelve el veredicto en menos de 1 segundo.

  • 24/30 features medidos en vivo: URL, TLS, redirects, HTML, DNS, WHOIS
  • 6 features con default (Alexa '22, PageRank '16 — servicios ya no existen)
  • Demo web interactiva: localhost:8000

Originalmente era el entregable principal de esta entrega; se decidió moverlo al laboratorio.

② Comparación de tiempos de inferencia

Se agregó como implementación adicional en esta entrega: benchmark de los 3 modelos bajo las mismas condiciones.

  • 50 repeticiones · 1 659 muestras · tiempo promedio por muestra
  • Métricas: avg, min, max, desviación estándar
  • Resultados guardados en reports/metrics.json
Resultados · 3 min

Comparación de modelos — test set (1 659 muestras)

Modelo Accuracy Precision Recall F1 AUC
Random Forest 0.972 0.969 0.981 0.975 0.996
SVM (RBF) 0.946 0.935 0.971 0.953 0.987
MLP (propuesto) 0.965 0.951 0.988 0.969 0.994

El MLP tiene el recall más alto (98.8%). En seguridad, el recall es la métrica clave: un falso negativo es un sitio phishing que llega al usuario.

Conclusiones · 1 min

Lo que construimos y lo que aprendimos

Modelo

MLP con 96.5% accuracy y 98.8% recall — el recall más alto entre los tres modelos evaluados

Sistema

Extractor de features en tiempo real + API REST + demo web — algo desplegable, no solo un experimento

Velocidad

20 µs de inferencia por muestra — irrelevante frente a la latencia de extracción de features

Limitación honesta: el dataset es de 2014. Las métricas pueden sobreestimar el rendimiento en ataques actuales.
