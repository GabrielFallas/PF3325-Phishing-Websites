Contexto

¿Qué queríamos resolver?

Durante el semestre entrenamos un MLP para clasificar sitios de phishing con el dataset UCI (11 055 muestras, 30 features). El modelo quedó guardado en disco con 96.5% de accuracy y 98.8% de recall.

El problema

Un modelo guardado en disco no sirve de nada si nadie lo puede usar. Necesitábamos una forma de que alguien mande una URL nueva y reciba un veredicto — sin conocer Python, sin tener el código.

La solución

Una API REST que recibe una URL, extrae los 30 features en vivo, corre el modelo y devuelve el resultado en menos de un segundo.

Arquitectura

Cómo está organizado el sistema

① Extractor de features

feature_extractor.py

Convierte una URL en los 30 valores que el modelo necesita. Hace requests HTTP reales, handshake TLS, parsea HTML y consulta DNS/WHOIS.

② Modelo + Scaler

best_model.keras
scaler.joblib

Se cargan una sola vez al arrancar. El scaler normaliza el vector antes de pasarlo al MLP.

③ API REST

api_phishing.py

FastAPI orquesta todo: recibe la solicitud, llama al extractor y al modelo, y devuelve el veredicto en JSON.

Arrancar: uvicorn src.api_phishing:app --reload → localhost:8000

Implementación

Carga lazy del modelo y predicción

El modelo y el scaler se cargan una sola vez la primera vez que se hace una predicción — no al arrancar. Esto acelera el startup del servidor.

def _load():
    global _model, _scaler
    if _model is None:
        _model = tf.keras.models.load_model(MODEL_PATH)
    if _scaler is None:
        _scaler = joblib.load(SCALER_PATH)
    return _model, _scaler

La función de predicción normaliza el vector con el scaler y pasa por el MLP. Devuelve probabilidades para ambas clases.

def _predict_vector(vector):
    model, scaler = _load()
    x = scaler.transform(
        np.array(vector).reshape(1, -1)
    )
    p = model.predict(x, verbose=0)[0][0]
    return {
      "label": "Legítimo" if p >= 0.5 else "Phishing",
      "confidence": p if p >= 0.5 else 1 - p,
      ...
    }
Implementación

El endpoint principal: POST /predict/url

# Schema de entrada
class URLRequest(BaseModel):
    url: str
    timeout: int = 6

# Endpoint
@app.post("/predict/url")
def predict_url(req: URLRequest):
    vector, provenance, info = \
        extract_features(req.url, req.timeout)

    result = _predict_vector(vector)
    result["info"] = info
    result["features"] = {
        name: {"value": val,
               "source": provenance[name]}
        for name, val in
        zip(FEATURE_ORDER, vector)
    }
    return result

Implementación

El extractor: 24 features en vivo, 6 con default

Medidos en vivo (24/30)

  • URL: IP, longitud, acortadores, @, subdominios, redirects
  • TLS: handshake SSL real, validez del certificado
  • HTML: anchors externos, formularios, iframes, pop-ups (BeautifulSoup)
  • Red: registros DNS, edad del dominio vía WHOIS

Default (6/30)

Dependen de servicios ya discontinuados:

  • web_traffic → Alexa (cerrado 2022)
  • Page_Rank → Google Toolbar PageRank (2016)
  • Google_Index, Links_pointing_to_page, Statistical_report

Se usan valores neutros y se reporta la procedencia de cada feature en la respuesta.

Conclusión

Lo que implementamos

Qué hace la API

  • Recibe una URL cualquiera
  • Extrae los 30 features en vivo (< 1 segundo)
  • Corre el MLP y devuelve veredicto + confianza + procedencia de cada feature

Decisiones de diseño

  • Carga lazy del modelo (no bloquea el arranque)
  • Pydantic valida entradas automáticamente
  • Provenance explícito para los 6 features con default
  • Demo web incluida en el mismo servicio
